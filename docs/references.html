Reference 01 — Product-Company Aesthetic

Resend (resend.com)

resend.com ↗ — Email API for developers

What to borrow

Dark-first aesthetic with a single accent color. Product-style hero: big headline, one-line description, two CTAs. Feature sections presented as clean cards with icons. The entire site feels like a product, not a person — which is exactly what we want.

→ We borrow: the product-company structure, dark palette, feature-card pattern

What to change

Resend uses purple/violet as its accent. We keep our cyan/blue gradient — it's already distinctive and maps to the "infrastructure monitoring" visual language. Their layout is more marketing-heavy; ours should be more data-dense (an engineer's site, not a marketing site).

→ We change: more data density, engineering-forward content, dual cyan/amber accents

Reference 02 — Changelog / Release Page

Linear Changelog (linear.app/changelog)

linear.app/changelog ↗ — Product changelog

What to borrow

Date-grouped entries with clear hierarchy. Filter tabs (All / Features / Fixes). Each entry has a title, description, and optional media. Clean vertical rhythm with generous whitespace. Treats the changelog as a first-class product page, not an afterthought.

→ We borrow: date grouping, filter tabs, changelog-as-product-page status

What to change

Linear's changelog is light-mode and editorial. Ours is dark and technical — styled like a system event log. We show commit SHAs, diff stats (+142 -38), and event-type badges (PUSH, CREATE, RELEASE). It's a changelog for an engineer, not a product announcement.

→ We change: event-log format, commit-level detail, monospace timestamps, diff stats

Reference 03 — Developer Infrastructure Aesthetic

Railway (railway.com)

railway.com ↗ — Infrastructure platform

What to borrow

Dark theme with colorful accents on a near-black background. Network/topology visualizations as hero elements. The "infrastructure as product" framing — deploys, logs, metrics presented beautifully. Status indicators with colored dots. Technical precision meets visual polish.

→ We borrow: topology visuals, status indicators, infrastructure-as-product framing

What to change

Railway is a multi-feature SaaS product. Our site is a personal portfolio — fewer pages, more focused. We don't need pricing or team features. The 3D/topology element should be more abstract and artistic, less literal UI. Our status bar is personal ("shipping · 142 commits this month"), not system uptime.

→ We change: personal voice, abstract 3D, fewer pages, human warmth in the data
